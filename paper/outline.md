## 0. 这一版相对上一版改了什么

上一版(重心第二次调整后)的立论是 **One Graph, Not N** —— 产物片数由连通性决定,
不由产物模板片段数决定。那个立论**保留**,但四轮新结果把它推到了更一般的形式,
同时推翻了其中三处说法。

| 变动 | 上一版 | 现在 |
|---|---|---|
| 立论范围 | 只讲产物侧片数 | 产物片数 / 反应物片数 / **键的归属**是同一条原则的三个推论 |
| 主证据 | 按反应算:225 复制 + 62 净化不过 + 7 手性 | 追加**逐 outcome 全量审计**:0/0/0 对 3688/40456/279,且有两列**逐字相同** |

## 2. 立论

### 一句话

> **模板的地盘,只有它亲自匹配到的那些元素;其余一切 —— 片数、键、模板之外的部分 ——
> 由底物的连通性决定。**

模板应用是对底物的**一次整体图重写**,不是"逐个模板片段各造一个分子"。
一旦从模板的**形状**去推结构,而不是从它**实际匹配到的东西**去推,错误就必然出现。

### 三个推论,三处实测

| | 推论 | 从模板形状推 → 错在哪 | 实测 |
|---|---|---|---|
| **P1** | 产物分子数 = 重写后图的连通分量数 | 逐产物片段各建一张图 → 共享原子被复制进每一片 | RDKit 逆向 3688 个 outcome 复制原子,凭空多出 40456 个重原子 |
| **P2** | 输入分子数同样不是模板的性质 | "N 个反应物模板 ↔ N 个输入分子"的位置式契约 → 分子内反应无从表达 | 301 条交白卷;`run_on_substrate` 命中 291 |
| **P3** | 键归模板管 ⟺ 反应物模板**亲自匹配到**了它 | "两端都被匹配就归模板" → 环闭合键被当成模板的地盘删掉 | 本实现自己的缺陷,70 条静默错误 |

**P3 是本文最有说服力的一条,因为它是我们自己犯的错。** 它证明这条原则不是事后
为已有实现找的说辞:同一个类别错误(拿模板的形状当事实)在我们自己的代码里也发生了,
按同一条原则修好,70 条静默错误归零。

三条推论的共同形式:**片数 / 归属 / 边界都是(模板, 底物)的联合性质,不是模板的性质。**

### 立体是第二乐章,不是主题

按实测配重:294 条"omgkit 命中而 RDKit 未命中"里,拓扑层面(原子被复制及其下游)
占 **97.6%**,四面体手性只占 **2.4%**,双键顺反 **0 条**。
立体那部分不删 —— 它解释了五态计划、隐式氢占位、腾空槽位这些真正精细的设计 ——
但它排在第二节。

## 3. 不变量(I1–I6)

全文用这六条串起来:**每条对应一个架构决策、一个可测判据、一行消融**。

| | 不变量 | 架构决策 | 判据 | 现状 |
|---|---|---|---|---|
| **I1** | **质量守恒**:每个底物原子在产物集合中恰好出现一次 | 所有产物模板建进同一张图;模板外只搬一次;按连通分量切分 | 逐 outcome 数重原子(与记录无关) | 本实现 0 / RDKit 3688 |
| **I2** | **参照系自洽**:产物里每个立体描述都表达在产物自己的参照系里 | 每次搬运显式求置换宇称;隐式氢以哨兵占位 | 与记录逐中心比宇称(不用 CIP) | 归因后引擎缺陷 0 |
| **I3** | **写法不变**:模板把等价的东西换个写法,产物不变 | 走两侧邻居序的置换宇称,不比标记字面 | 枚举一个中心的 24 种等价写法 | 本实现 24 种一致 / RDKit 给出 2 种对映体 |
| **I4** | **信息不丢**:模板没碰的立体要保住 | 顺反存成**参照原子**(与写法无关),不存方向键 | 归因中"记录·目标侧漏写"档 421 条 | 成立 |
| **I5** | **不凭空造**:底物与模板都没有的立体不得出现 | 五态计划的 `Drop`;派生属性重算不继承 | 归因中"输入侧没有"档 346 + 130 条 | 成立 |
| **I6** | **输出确定性**:`write(parse(write(m))) == write(m)` | 规范写法下参照原子按**规范秩**挑,顺反随之换算 | 8831 条语料上的不动点检查 | 2 条 → **0 条** |

I6 是本轮新增。它看着与反应无关,却是**基准判据成立的前提**:命中与否靠比字符串,
串本身不是不动点的话,判据就没有意义。

## 4. 章节骨架

### 1 Introduction

- 模板应用是逆合成、反应预测、规则挖掘的共同底座;下游一切结论建在它之上
- 这里的失效**是安静的**:拓扑、原子数、电荷、分子式可以全对,只有分子被多切了一刀,
  或者原子被复制了一份 —— 不报错、不告警
- 问题不在"没写立体处理",而在**从模板的形状推结构**
- 贡献:
  - **C1** 形式化:片数 / 键归属 / 边界都是(模板, 底物)的联合性质
  - **C2** 一个据此实现的架构,逐条给出消融证据
  - **C3** 五万条规模的双向验证:骨架**全部输出**零出错;立体在模板能表达的范围内 100%
  - **C4** 参照实现中两类系统性缺陷的构造性证明(质量不守恒、书写顺序依赖)
  - **C5** 方法学:命中率看不见"对的旁边还有错的";必须配逐 outcome 的守恒审计

### 2 Formulation —— 两层

**2.1 拓扑层(P1–P3)**:整体图重写 vs 逐片段构建。片数、键归属、边界。

**2.2 立体层**:三个参照系 × 四次搬运。

- **S**(底物):手性标记相对邻居的**存储序**;顺反可能只以方向键存在
- **T**(模板):标记相对**书写序**,而模板两侧的书写序**互不相同**
- **P**(产物):标记相对**构建序**

| | 搬运 | 正确变换 | 出错的样子 |
|---|---|---|---|
| **A** | 匹配与锚定 | 子图同构 + 映射号锚点 | 槽位判据看"原子有没有进产物"而非"还连不连着中心" → 重定基被静默跳过 |
| **B** | 模板意图解释 T(反应物侧) → T(产物侧) | 构型不变 ⟺ (标记相同) == (置换为偶) | 只比标记字面 → 产物侧对调两个取代基被读成"保留" |
| **C** | 构型搬运 S → P | 求 S 序到 P 序的置换,奇则翻 | 长度对不上就跳过 → 标记留在 S 的参照系里 → 镜像 |
| **D** | 写出 P → 字符串 | 存储序 ↔ 书写序的置换 + 隐式氢补偿 | 顺反的整体翻转自由度不定死 → 同一分子两串 |

### 3 Algorithm —— 十步流水线

| 步 | 做什么 | 关键决策 |
|---|---|---|
| 1 | VF2++ 逐反应物模板找匹配,取笛卡尔积 | 反应侧**不判立体** —— 模板跨工具流通,读得更严会让现成模板不出产物,而"少了产物"比"多了产物"难发现 |
| 2 | 建 `ReactantFacts`:按映射号记锚点、度数、模板写的手性、**模板侧邻居序** | 邻居序是后面判"保留还是翻转"的唯一依据 |
| 3 | **所有产物模板建进同一张图** | 逐产物建图会把共享原子复制进每一片(P1) |
| 4 | 原子构建:继承 → 模板覆盖 → **派生属性重算** | 自由基电子数由 Kekulé 结构算出;kekulize 排在自由基指派之前,继承它会留下底物才有的自由基 |
| 5 | 键构建:键级、芳香标志、方向、配位键朝向 | 方向**模板写全了才算表态**;配位键朝向靠端点顺序,照搬会把箭头反过来当场超价 |
| 6 | 搬运模板外的部分:从已保留原子出发遍历,每个原子只搬一次 | **只有反应物模板亲自匹配到的键才归产物模板管**(P3);建键按**源键下标**排,不按遍历发现顺序 —— 后者会打乱邻居序,产物变镜像 |
| 7 | **在全图上**重定手性 | 必须排在切分之前:切分保持邻居相对顺序,定基要看全图 |
| 8 | 重定顺反:用参照原子,不用方向键 | 反应会删掉承载方向的单键,双键没被碰过几何却没了 |
| 9 | **按连通分量切分** | 分子数由此产生,不由模板片段数产生 |
| 10 | 可选:两侧打上原子映射号 | |

**3.x 手性的五态计划**

```
(∅, ∅) → Inherit  两侧都没写,继承底物,之后重定基
(x, ∅) → Drop     作者先要求了构型又不再给出 → 该中心不再确定
(∅, x) → Set      模板写死,不再重定基
(x, y) → Retain / Invert,由两侧邻居序的置换宇称裁决
```

`Drop` 与 `Inherit` 的区别是**语义**而非细节:前者是作者的表态。
最后一档不能只比标记字面 —— 反例 `[C@:1](A)(B)C >> [C@:1](B)(A)C`。

**3.y 重定基的三个难角**

1. **腾空的槽位**:槽位空不空看"**还连不连在这个中心上**",不是看那个原子有没有进产物 ——
   原子可以活到**另一个产物片段**里去
2. **隐式氢占着一个顶点**:脱保护/脱羧把 D4H0 变成 D3H1。氢不是图里的节点,却占着
   四面体的一个顶点。因"邻居数对不上"跳过重定基 = 标记留在反应物参照系 = 镜像。
   做法:以哨兵参与置换
3. **一次换掉两个取代基**:对应关系不唯一,两种配对给出对映体。**必须挑明这是一个约定** ——
   另一种做法("不唯一就不定基")并非"不猜",而是猜了恒等置换。语料裁 2:1

**3.z 顺反:表达形式决定能不能活下来**

- 两种表达:方向键(相对键的端点顺序,**与写法绑定**)vs `stereo` + 参照原子(**与写法无关**)
- 反应会删掉承载方向的那根单键,双键明明没被碰过,几何却跟着没了 → 搬运前必须先感知成后者
- **模板方向键只有"写全"了才算表态**:一根孤立的 `/` 定不了几何(`F/C=CF`),
  照抄进产物会与另一侧继承来的方向凑成一对,两个参照系拼出任意几何
- 共轭链上一根方向键**同时贴着两根双键**:不能拿它去重算隔壁那根。感知的契约必须是
  "只新增,已有的一概不动" —— 包括不改成别的值

**3.w 输出侧的自由度**:同一约束片段内方向键可整体互换而不改变任何一对取代基的相对
位置 —— 对分子是真自由度,对**字符串**必须定死(I6)。

### 6.4 环大小扫描(`results/intra_salt.json`)

n 元内酰胺,正确答案恒为**一个**分子、n+1 个重原子。RDKit `>>A.B` 多出的重原子数
**恰好等于 n−4**(模板匹配 4 个环原子,其余被整份复制进两片):

| n | 4 | 5 | 7 | 12 | 20 | 25 |
|---|---|---|---|---|---|---|
| RDKit 多出 | +0 | +1 | +3 | +8 | +16 | +21 |
| omgkit 多出 | 0 | 0 | 0 | 0 | 0 | 0 |

n=4 那一行看着无害,其实是 P3 的入口:四元环上模板两端**直接相邻**,它们之间那根键
两端都被匹配、模板却没匹配到它。扫描从 n=4 起就是为了盖住这一档。

**组分括号救得回质量,救不回分子数**:

| | 分子间底物(应 2 片) | 分子内底物(应 1 片) |
|---|---|---|
| RDKit `>>A.B` | ✅ | ❌ 2 片,还多原子 |
| RDKit `>>(A.B)` | ❌ 1 片(内含 2 个连通分量) | ✅ |
| omgkit(两种写法结果相同) | ✅ | ✅ |

## 8. 方法学一节:命中率看不见什么(新增,C5)

这一节独立于任何实现,建议单独成节(或放进 Evaluation 的方法部分)。

**命中判据是存在量词。** "真值 ∈ 预测集合"约束的是集合里**有**什么,从不约束它**还有**什么。
一条逆向模板在同一个底物上通常匹配到好几个位点:不绕环的位点给出正确产物、反应照样
算命中;绕环的位点给出多切一刀的垃圾 —— 判据已经被满足了。

因此那 70 条静默错误:

| 检查手段 | 能否看见 | 为什么 |
|---|---|---|
| 命中率 | ✗ | 修前修后命中数一条不差 |
| 质量审计(按反应) | ✗ | 原子没多没少,只是连通性被改了 |
| 净化检查 | 基本 ✗ | 70 条里只有 8 条净化不过,其余 62 条两片都是**正常分子** |
| 逐条归因未命中 | ✗ | 这些反应**都命中了**,压根不在未命中集合里 |
| **新旧两版预测集内容逐条对拍** | ✓ | 唯一查得出的手段 |

**推论,写进正文**:凡是报告"命中率"的模板应用工作,都应当同时报告
**逐 outcome 的守恒审计**,否则"骨架无一出错"这类说法只对**未命中集合**成立,
而不对全部输出成立。本工作正是这样先说错、再自己查出来的 —— 如实写。

### 8.1 第二个洞:归因脚本静默跳过了它比不了的那些

并入大纲时把归因表加了一遍:**未命中 1288 条,逐中心定责只出 1286 条**。

差的 2 条 `omgkit_preds` 是空的。定责脚本要拿预测与真值逐个立体中心比对,
**没有预测就无从比起**,于是被跳过 —— 而"一个产物都没有"恰恰是最重的一档。
归因表因此看着干净:它只统计了能比的那些,而且不说自己漏了什么。

这 2 条正是 §6.10 那个缺陷。修完之后 1286 条未命中、1286 条归了因,缺口 0。

**做法上的结论**(与上面同源,建议合并成一段写进方法):

> 任何"逐条归因"的表格都要**与总数对账**,并且把对账写进脚本而不是留给读者去加。
> 一份归因表若只报它归了什么、不报它跳过了什么,那么最严重的失效 —— 严重到
> 连可比的输出都产不出 —— 恰好是它最容易漏掉的那一档。

已落实:`summarize.py` 现在算 `miss_attribution_gap` 并在非零时报警。
拿修前的数据跑,它输出"有 2 条未命中没被归因";修后为 0 —— 对账本身也非空过。
